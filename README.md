# Мониторинг льда Арктики — пилот L1/L2

Расширена **частичная карта кандидатов в льдины**: 5 участков по 50 × 50 км,
суммарно **12 500 км²** — в 25 раз больше прежней площади. Получено
5 570 оптических наблюдений кандидатов,
6 686 радарных целей и 12 групп повторных сигналов.
Подтверждённых стамух нет; вся Арктика детектором объектов ещё не обработана.
[Расширенные результаты](examples/expanded-map-2025-2026/README.md) ·
[Методика и запуск](docs/expanded-areas.md).

Большая географическая карта объединяет обзор Арктики, три месячные мозаики,
15 оптических кадров и 19 радарных проходов. Есть выбор дат, подробные фрагменты
при приближении, маски пригодности и фильтр повторных радарных целей.
Предыдущий расчёт 500 км² сохранён в [архиве](examples/object-map-2025-2026/README.md).

**Исправление от 18.09.2026:** старый июльский оптический пример пересчитан из-за
конфликта BOA offset в legacy-коллекции. По умолчанию используется Collection 1.
Прежние количественные значения отозваны; [подробности](docs/validation.md).

Добавлен **зимний обзор всей выбранной морской области российской Арктики за
декабрь 2025 — февраль 2026**: 5 310 сцен в каталоге, три мозаики по 100 сцен,
сетка 2 км и попиксельные даты/источники. Это обзор SAR и доступности съёмки;
карта отдельных льдин и стамух всей Арктики ещё не построена.
[Готовые карты](examples/winter-2025-2026/README.md) ·
[Методика, ограничения и запуск](docs/winter-atlas.md).

Исследовательский прототип: поиск открытых спутниковых сцен, выделение кандидатов
в ледовые объекты, сопоставление наблюдений, контроль давности и экспорт в QGIS.
Порог поиска — **эквивалентный диаметр 30 м**. Это не подтверждённая полнота обнаружения.
Малые объекты получают низкую уверенность; подтверждение стамух и происхождения
отколовшихся объектов требует отдельной проверки.

## Что реализовано

- Sentinel-2 **L2A**: публичный поиск Earth Search, чтение нужных фрагментов COG,
  индивидуальные scale/offset, облака/тени/NoData, NDSI, маска морской области,
  векторизация, площадь и эквивалентный диаметр.
- Sentinel-1 **L1 GRD**: поиск в CDSE, загрузка с токеном бесплатной учётной записи,
  граф предварительной обработки ESA SNAP, последовательный SAR worker, импорт калиброванного GeoTIFF,
  экспериментальное выделение ярких радиолокационных целей.
- Консервативное сопоставление объектов: расстояние, площадь, форма, неоднозначность,
  скорость и заданная оценка неопределённости; отдельные потоки SAR по орбите/поляризации.
- SQLite, повторный запуск без дублирования, сохранение исходных метаданных,
  конфигурационный отпечаток, повторные запросы при временных ошибках,
  атомарная запись JSON, журнал качества и GeoTIFF маски.
- Периодический оптический опрос, контейнер для самостоятельного сервера, тесты CI.

**Пока не реализовано/не валидировано:** обученный классификатор льдин/судов,
автоматическое подтверждение стамух, доказанное обнаружение откола, граф split/merge,
совместное совмещение SAR/оптики, региональная карта классифицированных ледовых объектов,
оценка полноты/ложных тревог на размеченной выборке, навигационная эксплуатация.
Граф SNAP необходимо проверить с установленной версией SNAP на реальном GRD.
`watch` по умолчанию запускает оптику; SAR включается явно через `--sar-gpt`.

## Почему 30 м — отдельный режим качества

| Источник | Уровень входа | Пространственные свойства | Роль |
|---|---|---|---|
| Sentinel-2 MSI | L2A | B03: 10 м; B11 и SCL: 20 м | Малые кандидаты в светлое время без облаков |
| Sentinel-1 IW GRDH | L1 | примерно 20 × 22 м, шаг 10 м | Дополнительные цели ночью/при облачности; 30 м ненадёжны |
| Sentinel-1 EW GRDM | L1 | примерно 93 × 87 м, шаг 40 м | Крупные объекты и ледовая обстановка, не 30 м |
| Landsat 8/9 Collection 2 SR | L2 | 30 м | Резерв для крупных объектов, адаптер планируется |
| VIIRS VNP29 / VJ129 | L2 | 375 м | Обзорный слой, адаптер планируется |
| MODIS MOD29 / MYD29 | L2 | 1 км | Обзорный слой, адаптер планируется |

Ресэмплинг B11 на сетку 10 м не превращает его в канал с разрешением 10 м.
Порог 30 м означает площадь не менее π × 15² ≈ 707 м²; на сетке 10 м это
минимум 8 пикселей. Узкая длинная льдина может иметь другой максимальный размер:
в версии 0.1 используется именно эквивалентный диаметр, а не длина.
Порог `reliable_diameter_m=100` — консервативная инженерная настройка, не результат
измеренной точности. `confidence` не является вероятностью.

## Быстрый запуск

Python 3.11+ (проверка разработки — Python 3.12). Из корня репозитория:

```bash
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -e ".[test]"
python -m pytest -q
ice-monitor search --sensor s2 --start 2025-06-01T00:00:00Z --end 2025-06-02T00:00:00Z
ice-monitor run --start 2025-06-01T00:00:00Z --end 2025-06-02T00:00:00Z
```

Без дат `run` выбирает последние 7 суток. Даты должны включать часовой пояс.
Все результаты по умолчанию попадают в `runs/kara/` и исключены из Git.
Другую папку указывать до подкоманды: `ice-monitor --output runs/test run ...`.

Пилотная область: небольшой морской участок **72.1–72.4° E, 73.0–73.15° N**,
восточнее острова Белый. Это технический участок, не всё Карское море и не
специально выбранный полигон подтверждённых стамух. Для прибрежного мониторинга
задайте рабочие полигоны в `config/kara_ocean.geojson`, вычитая сушу и острова
по проверенной береговой линии. Снег на суше спектрально похож на морской лёд.

Параметры — `config/kara.json`. После изменения параметров используйте новую
папку результатов: смешивание результатов разных настроек блокируется.
Не расширяйте пилот одной огромной рамкой: лимит 4 млн пикселей намеренный.

## Результаты

| Файл | Содержание |
|---|---|
| `observations.geojson` | История наблюдений; WGS84, ID, размер, движение, качество |
| `events.json` | Новое наблюдение или неоднозначность сопоставления; требует проверки |
| `status.json` | Ошибки, давность, последняя пригодная сцена, отпечаток конфигурации |
| `optical-status.json`, `sar-status.json` | Последний результат каждой ветки отдельно |
| `coverage.json` | Доля пригодного морского участка по каждой сцене |
| `scenes/<hash>/mask.tif` | 0 = нет выделенного кандидата, 1 = кандидат, 255 = нет пригодного наблюдения |
| `scenes/<hash>/scene.json` | Геометрии и происхождение результата |
| `state.sqlite` | Состояние обработанных сцен |

Откройте GeoJSON и GeoTIFF в QGIS. `newly_observed` не означает «только что откололась».
`stationary_candidate` не означает «стамуха». `grounding=unverified` сохраняется всегда.
Нулевая маска означает только отсутствие срабатывания выбранного детектора.
`stale` считается по возрасту наблюдения, а не по времени запуска программы.
`freshness_by_sensor` показывает давность отдельно для S1 и S2; свежий SAR не
снимает флаг `small_objects_optical_stale` для малых оптических кандидатов.

Пример архивной проверки: [docs/validation.md](docs/validation.md).

## Sentinel-1: отдельная последовательность

1. Бесплатная учётная запись [CDSE](https://dataspace.copernicus.eu/), установленный
   [ESA SNAP](https://step.esa.int/main/download/snap-download/) с Microwave Toolbox.
2. Найти доступные сцены и выбрать режим/поляризацию из метаданных:

```bash
ice-monitor search --sensor s1 --start 2025-06-01T00:00:00Z --end 2025-06-03T00:00:00Z
# UUID взять из catalogue-s1.json. Токен передать через CDSE_ACCESS_TOKEN.
ice-monitor download-s1 PRODUCT_UUID data/scene.zip
```

Токен выдаётся по [документации CDSE](https://documentation.dataspace.copernicus.eu/APIs/Token.html).
Не сохраняйте пароль или токен в репозитории. Загрузка GRD может занимать гигабайты.
Сейчас проверяется формат ZIP, но не сверяется контрольная сумма из каталога.

3. Граф `snap/s1_ocean.xml`: орбита → край GRD → тепловой шум → линейная Sigma0 →
   участок с запасом → коррекция на эллипсоид → GeoTIFF. Пример для IW/VH:

```bash
gpt snap/s1_ocean.xml -Pinput=data/scene.zip -Poutput=data/sigma0.tif -Ppolarization=VH -Pspacing=10 "-PorbitType=Sentinel Precise (Auto Download)" "-Pregion=POLYGON((72.0 72.9,72.5 72.9,72.5 73.25,72.0 73.25,72.0 72.9))"
```

Для свежих сцен может потребоваться `Sentinel Restituted (Auto Download)`.
Граф предназначен для этого морского пилота; проекция в нём EPSG:32643.
Для EW используйте шаг 40 м. Отсутствие агрессивного speckle-фильтра намеренно:
сглаживание способно уничтожить малые цели. Подавление ложных целей остаётся
задачей последующей валидации. Высотная модель суши не является батиметрией.

4. Проверить, что GeoTIFF содержит линейную Sigma0 нужной поляризации, затем:

```bash
ice-monitor ingest-sar --input data/sigma0.tif --datetime 2025-06-01T12:00:00Z --product-id REAL_PRODUCT_NAME --mode IW --polarization VH --band 1 --relative-orbit 123 --direction ascending
```

Дата, орбита, направление и поляризация в примере — **заменяемые значения**, брать
из конкретного продукта. Отрицательные dB-входы отвергаются; положительные DN
от Sigma0 автоматически отличить нельзя, поэтому калибровка — обязательный контракт.
SAR-детектор выделяет локальный контраст ≥6 dB и не различает лёд и судно.
Все SAR-цели пока имеют низкую уверенность; это диагностический слой.

## Периодическая работа

```bash
ice-monitor watch --interval-minutes 30
# При установленном SNAP и CDSE_ACCESS_TOKEN — обе ветки последовательно:
ice-monitor watch --interval-minutes 30 --sar-gpt /opt/snap/bin/gpt
# Разовый автоматический SAR-проход (по умолчанию не более 2 новых сцен):
python -m ice_monitor.sar_worker --gpt /opt/snap/bin/gpt --max-scenes 2
# Или отдельный сервер с Docker:
docker compose up -d --build
```

Это опрос каталога раз в 30 минут, **не получение снимка каждые 30 минут**.
Фактическая задержка состоит из ожидания съёмки, публикации и обработки.
Образ не содержит SNAP. Комбинированный запуск выполнять в среде с SNAP.
SAR worker получает режим/поляризацию/орбиту/время из каталога; записывает отдельный
`sar-status.json`, метаданные и журнал SNAP. Настройка `SNAP_ORBIT_TYPE` позволяет
выбрать `Sentinel Restituted (Auto Download)` для свежих сцен. Обновление истекающего
токена CDSE остаётся задачей оператора. Лимит новых SAR-сцен ограничивает объём
скачивания; `queued` показывает оставшуюся очередь. Обе ветки используют общую
базу последовательно; для независимого параллельного запуска нужны разные папки.
Один писатель на каталог результатов; параллельные запуски в одну папку не поддержаны.
Для первой версии разумный старт сервера — 4 CPU, 8–16 ГБ RAM, диск с запасом
под выбранный архив; это оценка, не замер производительности.

## Известные ограничения

- Оптические сцены над открытым морем могут отсутствовать; облачность, низкое солнце
  и полярная ночь не компенсируются частым опросом.
- Основная ветка работает с одним провайдером COG; при его сбое статус становится
  ошибочным, предыдущие наблюдения сохраняются. Автоматический резерв CDSE ещё не подключён.
- Тайл за тайлом: нет мозаики соседних плиток одного пролёта. Повтор в течение
  30 минут не засчитывается как независимое наблюдение для трекинга; часть покрытия
  может не войти в треки. Маски и исходные кандидаты каждой сцены сохраняются.
- Упрощённый трекер требует однозначной пары по форме и расстоянию. В плотном льду
  он часто разрывает треки, а одиночные похожие объекты может спутать. Вращение,
  таяние, слияния и отколы требуют более развитого алгоритма и разметки.
- Пропущенные сцены не вызывают события «объект исчез». Прогноз дрейфа не реализован.
- Автоматической батиметрии, проверки киля, классификации айсбергов и проверки по AIS нет.
- История сохраняется локально без политики очистки; её нужно задать для эксплуатации.
- Задержанные данные старше окна 7 суток требуют ручного исторического запуска.
  История треков пересчитывается; позднее добавление ранних сцен может изменить ID.
- Комбинированный `watch` ждёт завершения SNAP, поэтому тяжёлая обработка SAR
  задерживает следующий оптический опрос. Для промышленного контура нужны отдельные очереди.
