# Расширенная обработка зимних участков

Пять участков по 50 × 50 км: Баренцево, Карское, море Лаптевых,
Восточно-Сибирское и Чукотское моря. Номинальная площадь — 12 500 км²,
в 25 раз больше предыдущего расчёта. Это пять отдельных участков,
а не сплошное объектное покрытие российской Арктики.

Используются только открытые исходные Sentinel-1 IW GRDH L1 и Sentinel-2
Collection 1 L2A за зиму 2025/26. Оптические наблюдения доступны в феврале.
Контуры остаются кандидатами; независимой проверки льдин и посадки льда
на грунт нет. Порог эквивалентного диаметра 30 м не означает доказанную
полноту обнаружения объектов такого размера.

## Как расширяется площадь

Планировщик заново ищет повторные IW-проходы, пересекающие увеличенный участок.
Предпочтение отдаётся серии одного спутника и относительной орбиты, с не менее
чем тремя наблюдениями и интервалом минимум 24 дня. Если край полосы не закрывает
всю область, он сохраняется как пробел: соседняя вдоль трассы сцена не расширяет
полосу поперёк трассы. В этом запуске выбрано 19 SAR-наблюдений: по четыре
в четырёх морях и три в Восточно-Сибирском море.

Оптический план содержит по три разные даты на море. Соседние гранулы
объединяются только внутри одного `s2:datatake_id`. Предварительная оценка
облачности на сетке 100 м используется только при выборе входов. Итоговая
маска качества и поиск объектов выполняются на сетке 10 м; канал SWIR и SCL
имеют исходный шаг 20 м. Предварительная доля ясных пикселей не подменяет
фактически пригодную площадь после обработки.

Загрузка идёт блоками до 20 × 20 км. Затем блоки собираются в единый растр
50 × 50 км, и детектор обрабатывает его целиком. Поэтому технические границы
блоков не становятся границами объектов. Поляризации SAR сохраняют отдельные
маски достоверности: отсутствие пригодного cross-pol не удаляет co-pol из
расчёта его фоновой яркости.

Для каждой мозаики сохраняется растр `source-index.tif`. У объекта `frame_id`
обозначает кадр карты, `source_id` — исходную сцену, давшую больше всего его
пикселей, `source_ids` — все участвовавшие сцены. Пересечение стыка сцен
помечается `multi_scene_boundary`. Источник объекта может отличаться от первой
сцены мозаики. Для SAR сохраняются ссылки на реально использованные измерения,
аннотации, калибровочные таблицы и шум.

## Площадь и интерпретация

В `summary.json` приведены номинальная площадь, площадь морской маски и
объединение пригодных пикселей по датам отдельно для оптики и радара.
Объединение по датам не является одновременным покрытием. Файлы
`masks/union/*.tif` позволяют проверить расчёт. За пределами маски пригодности
нет оснований делать вывод об отсутствии льда.

Используется прежняя грубая береговая маска Natural Earth 1:50 млн с отступом
1 км. Она не предназначена для точной прибрежной классификации на масштабе
30 м. Геопривязка и калибровка SAR остаются экспериментальными, без независимого
сравнения со SNAP и без уточнённой орбиты. Радиолокационные цели могут быть
торосами, судами, припаем и другими отражателями.

Стабильность оптического контура к изменению порога не подтверждает, что это
одна физическая льдина: возможны объединения и разделения объектов. Счётчики —
наблюдения по датам, не количество уникальных льдин. Повторная неподвижная
радарная цель — гипотеза; она не становится подтверждённой стамухой.

## Запуск

Сначала построить зимний каталог и проекционную основу по
[инструкции обзора](winter-atlas.md). Затем из корня репозитория:

```bash
python -m pip install -e ".[test,plot,objects]"
python -m ice_monitor.expanded_plan --base-plan config/object_validation_regions.json --overview runs/russian-arctic-winter --output runs/expanded-50km --side-km 50
python -m ice_monitor.expanded_processing --root runs/expanded-50km --overview runs/russian-arctic-winter --sensor optical
python -m ice_monitor.expanded_processing --root runs/expanded-50km --overview runs/russian-arctic-winter --sensor sar
python scripts/export_expanded_results.py --root runs/expanded-50km --overview runs/russian-arctic-winter --output runs/expanded-map
python scripts/validate_expanded_results.py runs/expanded-map
python -m http.server 8767 --bind 127.0.0.1 --directory runs/expanded-map
```

Открыть `http://127.0.0.1:8767/map.html`. Папка `images/` должна оставаться рядом
с картой. Общий вид использует уменьшенные изображения, а при приближении
подгружаются локальные фрагменты с шагом 10 м. WebP нужен только для отображения;
измерения выполняются по исходным числовым растрам. По ссылкам источников
потребуется интернет; сама карта не использует внешние картографические сервисы.

Обработка допускает `--regions kara,laptev`. Независимые процессы можно
запускать для непересекающихся пар «море + сенсор»; два процесса не должны
одновременно писать один кадр. Завершённые кадры с совпавшей конфигурацией
повторно не рассчитываются. Экспорт проверяет завершение всех запланированных
кадров и отказывается выдавать неполный набор как готовую карту.

## Проверки

40 автоматических тестов прошли локально. Добавлены проверки покрытия блоками
без пропусков и наложений, отказа при несовпадении площади или проекции, сохранения независимых масок SAR, атрибуции сцены по
пикселям объекта и эквивалентности ускоренного расчёта IoU прежнему алгоритму.
В центральных 10 × 10 км четырёх проходов Баренцева моря медиана и 95-й
перцентиль абсолютной разницы co-pol с прежним расчётом равны 0 dB; различие
масок конечных значений не превышает 0,0029%. Это проверка согласованности
расширения, не независимая оценка точности спутникового продукта.

Основная методика и первичные источники: [object-map.md](object-map.md).
